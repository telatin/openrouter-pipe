# Release notes pending

## New

- **Cost governor plugin** — records each request's real cost per user in an append-only ledger and enforces calendar-month limits by Open WebUI group, with an optional free fallback model once a user is over. See `docs/plugins_cost_governor.md`.
- **`HIDE_COST_FROM_USERS`** (default on) — the cost is no longer sent to Open WebUI in usage objects or shown in the final status line, so it is not stored on messages or visible in the message info tooltip. Set it off to restore the previous behaviour.

## Behaviour changes

- **Gemini thinking budget, `0` now turns thinking off for the whole Gemini family** — `GEMINI_THINKING_BUDGET=0` only worked on Gemini 2.5; on Gemini 3 thinking stayed on. It now reaches every Gemini model. Mandatory-reasoning rows (Gemini 3 Pro, 2.5 Pro) still cannot stop thinking, and other valve values are still ignored on Gemini 3.
- **A preset Fusion turn is no longer retried on chat completions** — a failed `/responses` call for `openrouter/fusion@preset/<slug>` was re-sent by `AUTO_FALLBACK_CHAT_COMPLETIONS` without the Fusion entry, giving a flattened transcript. The retry no longer happens: the provider's refusal reaches the person and the turn archives as `error`, not `complete`. Non-Fusion fallback and `enabled: false` are unchanged.
- **A per-model advanced parameter now schedules the metadata pass** — changing a `disable_*` flag (e.g. `disable_web_tools_default_on`) in Open WebUI's model editor did nothing until something unrelated changed. Saving the model now takes effect within one model-list build.
- **Switching the last sync valve off now detaches on the next pass** — turning off the last sync valve left attached panels in place until an unrelated setting changed. An on-to-off change now schedules a pass that detaches them.
- **Video, Continue after a Stop** — Continue after Stop now waits for the job already running instead of submitting a second one, which downloaded, stored and billed the same `job_id` twice. A Continue minutes later waits for the render already paid for.
- **Video turns and the circuit breaker / session log** — a video turn with a complete answer now resets the user's circuit breaker. A turn refused before sending is archived as `error` naming the control (e.g. `MAX_CONCURRENT_VIDEO_GENS_PER_USER`, or the missing prompt) instead of `complete`. A stopped turn still archives as `cancelled`.
- **A turn's address checks now share one budget** — the conversion leg used its own budget, so a request could spend up to twice `ADDRESS_CHECK_BUDGET_SECONDS` (20 s plus 20 s) and re-resolve links. It now uses the request's budget. **What a person can notice:** a picture-heavy turn can see `could not be checked in time, so it was not sent`.
- **The `/responses` leg now gates the media it forwards** — media refused for `/chat/completions` was forwarded unchecked on `/responses`. It now drops blocks with cleartext `http://` links (unless `ALLOW_INSECURE_HTTP` and `ALLOW_INSECURE_HTTP_HOSTS` permit), Open WebUI file paths, undialable schemes, bad `data:` payloads and `input_audio` URLs. Each is reported once as `Images: skipped N (<reason>).`
- **A tool picture the inliner cannot name is skipped and named, not fatal** — a tool picture whose Open WebUI file path yields no id used to end the whole turn with a "file is gone" card. It is now dropped, the request still goes out, and the turn reports `Images: skipped N (a picture naming ... cannot be read from Open WebUI storage).`
- **Per-user "How long to keep reasoning" now defaults to the whole conversation** — per-user `PERSIST_REASONING_TOKENS` now defaults to `conversation` instead of `next_reply`, matching the site-wide valve. Chosen values are kept; longer chats replay more reasoning, costing input tokens.
- **Tools are no longer sent in strict mode by default** — `ENABLE_STRICT_TOOL_CALLING` now starts off and tools go out with `strict: false`, because strict mode made OpenAI refuse every request offering `ask_user`. **Migration:** tick the valve to restore strict schemas.
- **A background task on a picture-only or video-only model is skipped, not sent** — with no Task Model set, title, tag and follow-up tasks on a model with no `"text"` output failed, logged an ERROR and toasted a failure card (GitHub issue #61). They now return an empty answer: the first message becomes the title, with no tags, follow-ups or card. The first skip logs a WARNING pointing to **Admin Settings > Interface**.
- **A video model's own instructions now apply on "use my prompt verbatim" turns** — verbatim turns dropped the deployment's system prompt. The instructions are now sent ahead of the scene on both arms, and the footer adds one line saying so. No valve change.
- **Video generation, dual models** — a model in both the chat and video catalogues now publishes one picture verdict: `capabilities.vision` and `capabilities.file_upload` follow the merged features, so a video row taking a first frame gets the `vision` box. Other capability boxes are unchanged.
- **A tool call the pipe gave up on is now counted as a failure on the dashboard** — calls cut by a full tool queue or by `TOOL_IDLE_TIMEOUT_SECONDS` are now reported, and the Live row returns to `streaming` instead of staying on `status: "tool:<name>"`. **Not comparable across this release:** `tools_failed` in earlier usage rows undercounts.
- **Pipe dashboard, API-key callers** — the dashboard action route now uses `get_verified_user`, so an `sk-` API key is admitted instead of refused. Requests without `Authorization: Bearer` are still refused. Access follows `auth.enable_api_keys`, `features.api_keys` and `auth.api_key.endpoint_restrictions`; a `401` now carries Open WebUI's message.
- **Admin's Max Upload Size, no longer gated on the RAG bypass flag** — with `rag.bypass_embedding_and_retrieval` on, the pipe ignored the admin's Max Upload Size and allowed a `REMOTE_FILE_MAX_SIZE_MB` download. The stored cap now binds either way.
- **Plaintext HTTP allowlist, a bare entry names one port** — an `ALLOW_INSECURE_HTTP_HOSTS` entry without a port now admits port `80` only; it used to open every cleartext port. **Migration:** add `host:port` entries (e.g. `internal.svc:6379`) for other ports. `https://` is unaffected.
- **An SVG a person attaches, a tool hands over, or the model wrote is not sent to the provider** — SVGs are now refused on every picture path, shown as `Images: skipped N (not identifiable as an image).`, and not counted against `MAX_INPUT_IMAGES_PER_REQUEST`. Other `image/*` types still go. Generated SVGs are still stored and drawn but not re-sent on later turns.
- **A file's name can no longer carry the pipe's own transport markers** — marker lines such as `[P:final_answer]: #` in a caller's `input_file.filename` could be misread by replay, splitting replies. They are now stripped; ordinary names like `[2026] report.pdf` are unchanged. A name of only markers loses `filename` and the file goes out on its `file_id`.
- **Pipe Dashboard write gate** — with `BYPASS_ADMIN_ACCESS_CONTROL=false`, a second administrator who is not the owner or a write-grantee is no longer refused operator actions, and an admin whose `Pipe Dashboard` row was never inserted is no longer locked out. The read gate still honours the valve.
- **Two installed copies of the pipe no longer share one dashboard** — dashboard bindings are now keyed by `Pipe.id`, so each copy handles its own requests and events. The action route takes `pipe` in the body and answers `404 {"error": "unknown pipe"}` for an unknown id. **A dashboard panel saved in a chat before this change** answers `unknown pipe` on Config and Update until reopened.
- **Gemini 2.5 thinking, hidden reasoning traces** — `reasoning.exclude` of `true` no longer defeats `GEMINI_THINKING_BUDGET`: with `0` the off holds as `{"effort": "none"}`, and `reasoning.max_tokens` is kept at a nonzero budget. On Gemini 2.5 Pro the refusal status line now fires.
- **Video intent classifier, a retired Task Model is now named** — the warning for a Task Model the host no longer publishes now names the id (`the host no longer publishes 'ext-4o'`) instead of reading like an unset row. No valve change.
- **A housekeeping task that recovers is heard about again the next time it fails** — the task-failure toast latch was never cleared, so a second outage after a recovery stayed invisible. A successful task now clears its chat's record so the next failure toasts again.
- **`logit_bias`, the text an admin typed, is decoded instead of destroying the request** — Open WebUI's text form (`"1234:100, 5678:-50"`) caused `ValidationError` on every turn or task using it. It is now converted to a mapping with biases clamped to `[-100, 100]`; unparseable values are dropped with a warning. `/responses` still drops the field.
- **Video intent classifier, retired Task Models** — a Task Model missing from a non-empty `request.app.state.MODELS` is now skipped, ending up to four billed `Model not found` attempts per video turn and the false breaker arming. The turn takes the `no_task_model_candidates` path.
- **Tool breaker's out-of-service notice** — the notice could be silently dropped after `TOOL_BATCH_TIMEOUT_SECONDS` or overrun `TOOL_IDLE_TIMEOUT_SECONDS`. Its bound now starts when it runs and respects the idle allowance, and a `WARNING` names the valve that cut it.
- **A refused Continue no longer loses the answer it was continuing** — when the admission gate refused a streamed turn, a `channel:` chat got no error card, and on a **Continue** `Server busy (503)` replaced the answer. The card is now published and the answer stays.
- **A skipped oversized image names the kind of file, not the caller's path segment** — the log record now reads `Skipping an attached image (image): ...` instead of the caller-written file id. The cause, limit and the `Images: skipped 1 (larger than the 1048576-byte inline limit).` status are unchanged.
- **A file a tool returned is inlined, not forwarded** — a `function_call_output` with a list of `input_text` / `input_image` / `input_file` parts is now resolved instead of flattened, so an `input_file` naming `/api/v1/files/<id>/content` no longer reaches OpenRouter with an Open WebUI path and `?token=`.
- **A cancelled attachment read reclaims its copy** — cancelling `materialize_owui_file_to_temp` now unlinks the private temp copy; a Stop used to leave a full copy on disk. TODO T637 (temp from a failed copy) stays open.
- **Two refusal cards stop appearing for block spellings that carry a real source** — file blocks naming a document under `id`/`url` and an `input_image` with a `file_id` are now sent instead of reporting `Files: skipped 1 (has no readable source).` or `Images: skipped 1 (an image carried no picture data).`. Stock Open WebUI 0.11.4 writes neither spelling.
- **A remote picture whose download the cap aborted is no longer forwarded as its link** — a transfer aborted by `REMOTE_FILE_MAX_SIZE_MB` used to be forwarded as a link anyway. It is now refused with `Images: skipped N (could not be fetched, so it was not sent).`. Other failures still forward the link. (T1283)
- **Secret valve values, a passphrase typed with the `encrypted:` prefix** — a secret typed starting `encrypted:` was stored in plain text in the valve row on installs with default `ENABLE_VALVE_ENCRYPTION`. It is now sealed, and the value read back is unchanged. Earlier prefixed values keep working and are rewritten on the next Config save.
- **Session log assembler, one offer per pass** — a turn already offered or failed in a pass is no longer re-offered, which burned the whole `SESSION_LOG_ASSEMBLER_INTERVAL_SECONDS` and never reached later turns. `SESSION_LOG_LOCK_STALE_SECONDS` backoff is unchanged.
- **Artifact encryption on a schema-qualified deployment** — with `DATABASE_SCHEMA` set, the artifact store could not read Open WebUI's `function` row, so after a `WEBUI_SECRET_KEY` rotation artifacts were stored in plaintext. It now reads the correct schema; the key-guard WARNING may appear for the first time, so re-enter the key.
- **Chat-message writes are gated on ownership** — A reply's error note, Fusion snapshot and turn metadata (`sources`, `annotations`, `reasoning_details`) are now written only to a saved chat the asker owns (any saved chat for an admin). If the ownership check cannot run, nothing is written. The Fusion panel and loop-limit note are no longer persisted on Temporary Chats or channels, though still delivered live.
- **Citation notices** — The "unrenderable citation type" notice now names the answer the reader actually sees, not a discarded retry. A turn with no such citation in its surviving answer, or ending in a failure card, gets no notice.
- **Stalled accepted bodies** — When OpenRouter accepts a request and the body stops arriving, it is now one POST showing the connection card. An `Idle read timeout`, reset socket or `Total request timeout` used to burn the full retry budget and bill several answers, and non-streaming legs blamed the operator's proxy. No valve changed.
- **Tool pictures, the sanitizer's leg** — A tool-result picture link that fails the `ENABLE_SSRF_PROTECTION` check is now refused on plain HTTP too; with `ALLOW_INSECURE_HTTP` on it used to be forwarded. A check with no verdict in time is refused as `could not be checked in time` (cause `uncheckable_tool_picture`), not reported as a failed download.
- **Tool calling, a caller's own `strict` on a Responses-shaped tool** — A caller's `strict` is now forwarded instead of dropped. Since `/responses` defaults an absent `strict` to `true`, opt-ins arrived non-strict and opt-outs strict. Tools without `strict` still go out without one.
- **Video generation, status-poll errors** — `VIDEO_STATUS_POLL_MAX_ERRORS` still bounds consecutive status errors, and now also total errors across one watch (the value times five), so an intermittently failing endpoint stops being watched. The resumable still-running card and Continue Response still work. A fault in the pipe's own code, such as `RuntimeError("Session is closed")`, is no longer counted or retried; it ends the watch at once, is logged as the pipe's own, and leaves the resumable card instead of a final failure card.
- **OpenRouter Web Tools filter id** — The warning that the Web Tools function id is held by a row this pipe does not own now re-warns after 300 other causes have been armed, instead of going silent after the first emission.
- **Pipe dashboard, viewer payload** — The live dashboard payload no longer carries the data-dir path, so read-only viewers cannot learn the server's filesystem layout. The Disk card is unchanged, and the path remains on the admin-only Config tab's `Session log directory` row.
- **Temporary chats, marker records** — Three streaming marker records now name a temporary chat's socket id as `<not retained>`; it had reached the dashboard's log view. Levels, counts and reasons are unchanged. Saved and `channel:` chat ids are still named.
- **Provider errors** — A provider error body containing an unpaired surrogate now reaches the error card with that character shown as the replacement character. It used to cause an HTTP 500 and lose the WARNING record and the whole session-log archive.
- **Tool pictures** — A faulted SSRF address pool (for example after a `MAX_CONCURRENT_REQUESTS` change mid-turn) now costs only the picture, not the reply. The turn is sent without the link and the person sees `Images: skipped 1 (could not be checked in time, so it was not sent).` It used to produce an `Unexpected Error` card.
- **Temporary chats** — The reply hold no longer keeps a temporary chat's socket id. The 15-minute hold, 64 MiB pool ceiling and release timing are unchanged, as are saved and `channel:` chats.
- **Video generation, a temporary chat** — The video intent classifier no longer sends a Temporary Chat's socket id in its task-model request. A temporary chat id is never sent, and `SEND_CHAT_ID` off means no chat id at all; saved and `channel:` chats keep their id on the valve.
- **Video, channel resume** — A video resume in a `channel:` chat is now authorised against the channel before the stored turn is read. A requester the channel does not admit reads nothing and the turn starts a new, separately billed job. Open WebUI's own route already refuses such requesters, and members resuming their own turn are unaffected.
- **Pipe Dashboard, a second administrator** — With `ENABLE_ADMIN_WORKSPACE_CONTENT_ACCESS` off, an administrator who neither owns the `Pipe Dashboard` model row nor holds a grant now loses the dashboard, including `config_get`, matching Open WebUI's own rule. The shipped default, the row's owner and grant holders are unaffected. A refused admin sees the access-denied card.
- **Dashboard Update tab, restore on a package or stub install** — Restore is now refused with the `package_mode` outcome Update gives, instead of overwriting the install with an older bundle snapshot. The Restore button is hidden there; snapshot list and Delete are unchanged.
- **`file_url` with no scheme** — A `file_url` without a `scheme://` (such as `/etc/passwd` or `169.254.169.254/latest/meta-data/`) is now refused, and the person sees `Files: skipped N (served from a link that is neither http nor https, which is blocked by security policy).` `ENABLE_SSRF_PROTECTION=False` does not restore these. Inline base64, `data:` URLs and Open WebUI file paths are unchanged.
- **Multi-worker Redis deployments** — An admin dashboard config save or unattended update no longer closes the Redis client shared with Open WebUI's websocket bookkeeping (`WEBSOCKET_MANAGER=redis`). The visible effect was `Session pool cleanup failed. Retrying.` and `Unknown receive error` lines around a save.
- **Web-Tools filter valves, the default the pipe seeded** — Turning off both `AUTO_ATTACH_WEB_TOOLS_FILTER` and `AUTO_INSTALL_WEB_TOOLS_FILTER` now also releases the seeded `defaultFilterIds` entry, which used to be left behind with no panel. The `AUTO_ATTACH_WEB_TOOLS_FILTER` help text now says the install valve must be off too.
- **Native image filters, a superseded panel** — A panel retired as superseded is now removed from both `filterIds` and `defaultFilterIds` on its model rows, with either image valve on. Before, it could stay attached and default-on.
- **`meta.builtinTools` the pipe wrote from a File-context untick** — The pipe now writes `builtinTools.files = false` only on media models whose own media rule caused the `file_context` untick, so an operator who unticks it on a text or vision model keeps the chat-file tools. Rows already carrying `builtinTools.files = false` keep it; untick the box in the model editor or wait for the marker work (B682/T971).
- **Pipe shutdown no longer drops a session-log write that was still in flight** — A turn cancelled by `close()` now gets its terminal log segment written before the artifact store closes, even past the 5-second drain budget. `close()` stays bounded.
- **Usage collection, a rotated `WEBUI_SECRET_KEY`** — When the stored valve row cannot be read (such as after a `WEBUI_SECRET_KEY` rotation), the usage writer now logs one latched WARNING naming the read. Before, the Usage tab went empty silently. Nothing is written and the batch is still dropped.
- **Video generation, machine callers** — A failed video turn for a caller with no chat now returns an HTTP error instead of a `200` with a Markdown card: the resolved status in `error.code` (`502` for a proxy-rewritten body), or `500` with `Video generation failed.` for a pipe-owned fault. A rewritten poll response no longer echoes an excerpt. Streamed callers, Anthropic Messages paths (`/api/v1/messages`, `/api/message`), and the per-user cap and missing-prompt refusals still get cards.
- **Provider routing panels** — A model's provider-routing filter is no longer detached when two model-list refreshes overlap. A pass that never obtained an answer leaves every filter list unchanged.
- **A model-list refresh that outlives its generation no longer writes** — A `/api/models` refresh still running when a hot reload, valve save or deleted function row retires its Pipe now skips all writes after the catalogue load. Before, two generations could write the same rows.
- **Media on the `/chat/completions` leg** — Turns on the chat endpoint (`DEFAULT_LLM_ENDPOINT=chat_completions`, `FORCE_CHAT_COMPLETIONS_MODELS` or `AUTO_FALLBACK_CHAT_COMPLETIONS`) now judge media links by the `/responses` rules: HTTP only with `ALLOW_INSECURE_HTTP` and an allowlisted host, scheme, own `/api/v1/files/` links, and the inline size bound. A refused block is dropped and named as `[An attached item was not sent: ...]`. A `data:` video is now held to `BASE64_MAX_SIZE_MB`.
- **A refused tool picture on the unstreamed `/chat/completions` route** — A tool picture dropped by the chat-leg conversion (over `BASE64_MAX_SIZE_MB`, cleartext `http://`, unusable scheme) is now reported on its turn as `Images: skipped N (<reason>).` Before, the refusal was silently dropped.
- **A refused picture no longer re-reports itself on every later turn** — With the default `Image input reuse`, a picture refused earlier (such as one over `Maximum base64 upload size`) was re-reported on later turns within `Image reuse window`. Refused pictures now never enter the reuse pool and are reported once, on their own turn.
- **A refused file is named on the turn that carried it and on no later turn** — A `Files: skipped 1 (...)` status was repeated on every later turn replaying the history, and for callers with no `chat_id`/`message_id` it was also joined into `choices[0].message.content`. `_NOTICE_LOOKBACK_TURNS` is now `0`, so a refusal is reported on its own turn only, as `docs/multimodal_ingestion_pipeline.md` states.
- **Presets** — A request using the dispatched spelling `<base>@preset/<slug>` is now served instead of refused with the `Blocked model message`. A preset turn also uses its base model's real context window instead of the 128 000-token fallback.
- **image generation, a rewritten response body** — When something in front of OpenRouter returns an error page or WAF challenge for the image endpoint, the failure card now shows that text in full in a quoted code block, so embedded beacons and phishing links are inert. The endpoint and upstream `Content-Type` remain ordinary prose.
- **Image generation, caller with no chat** — An image request failing on a provider rejection or proxy-rewritten body now returns an HTTP error envelope to a caller with no `chat_id` and `message_id`, with the upstream status in `code` (`502` for a rewritten body). Callers in a chat keep their card, and pipe-owned faults still return readable text; see [Error handling](docs/error_handling_and_user_experience.md).
- **Session log** — With `SESSION_LOG_STORE_ENABLED` off (the default), the pipe no longer builds DEBUG request and response payloads. The in-memory session log still fills with all other records, so the dashboard's **Log buffers (RAM)** counters are not 0. `Log verbosity level` `DEBUG` still prints payloads to the console.
- **Artifact retention sweep** — A cleanup pass whose Redis cache purge could not finish no longer deletes anything, so rows are not deleted while cache entries naming them stay readable. A faulted cycle logs one warning and retries on the next interval. Healthy passes and deployments with the Redis cache valve off are unchanged.
- **Filter rows, two pipe copies** — With two pipe copies, each now reads only its own filter rows (Web Tools toggles and cost ceiling, and the image-generation model). A row stamped with another copy's install record is no longer read or executed. The second copy gets its own image-generation filter row after the next model refresh.
- **Timing profiler** — `ENABLE_TIMING_LOG` now writes only `timing.jsonl`. The unused per-request in-memory copy of timing events and its accessors are removed; the file's contents are unchanged.
- **Video attachments, the size the pipe measures** — A clip whose real video size is below the model's pixel floor, such as an `.avi` or ProRes `.mov`, is now withheld with a notice naming that size. A clip with cover art first is no longer wrongly withheld.
- **Endpoint valves** — A `FORCE_CHAT_COMPLETIONS_MODELS` or `FORCE_RESPONSES_MODELS` entry naming a base model now also matches its suffixed spellings (`:free`, `:thinking`, `:nitro`, `:exacto`, `:floor`, `:online`, dated forms). A pattern naming a tag or date still matches only that spelling, and `:preset/...` is left alone.
- **Open-WebUI tool mode** — a tool call Open WebUI runs now shows its card as soon as the model names the tool, and the dashboard's live view shows the running tool.
- **Pipe dashboard, deleted function row** — deleting the pipe's function row now releases the live dashboard on the serving worker and lets the pipe finish in-flight requests and close, instead of holding resources until restart. Happens whether or not `PIPE_DASHBOARD_ENABLE` is on; other workers release at their next hot reload.
- **Pipe dashboard, usage collection switched on after start** — usage collection switched on after boot now records usage and runs the abandon sweep without a restart. Before, abandoned sessions piled up and the Usage tab's **Failed** count came up short.
- **Pipe dashboard, session tracker bound** — the tracked-session registry is now bounded. At the bound the stalest entry is finalized as `failed` with one usage row, and a latched warning names the bound. The **Active** tile and Live table (30 newest rows) are unchanged.
- **`/chat/completions`** — a streaming body the provider accepted and then lost is no longer re-sent, so it costs one POST instead of `1 + TRANSIENT_RETRY_MAX_ATTEMPTS`. Unusable-but-complete bodies and connections that never reached the provider are still retried. This is the fallback leg (`AUTO_FALLBACK_CHAT_COMPLETIONS`, `FORCE_CHAT_COMPLETIONS_MODELS`, or `DEFAULT_LLM_ENDPOINT` = `chat_completions`).
- **Streaming** — a frame discarded by the drop valve no longer closes the retry barrier. With `MIDDLEWARE_STREAM_QUEUE_MAXSIZE` above `0`, a full buffer could drop text and end the turn on a card; such a turn is now retried. A frame the buffer did take still ends the turn.
- **Session log** — a turn the pipe refused before sending is now archived as `error` instead of `complete`, with a `reason` naming the refusing control. This covers the eight pre-send refusals (ZDR, endpoint-override conflicts, Fusion forced to `/chat/completions`, unloadable attachment, model restrictions). The card shown is unchanged.
- **session log, per-record bound** — a record carrying a whole payload is now cut at 16,384 characters and marked `...(truncated: 1,234 characters omitted)...`. This covers SSE events, request headers and payload, response payload and error response. Smaller records are unchanged; the `SESSION_LOG_MAX_LINES` and `OPENROUTER_ERROR_TEMPLATE` help text now match (error excerpt cut at 8,192).
- **artifact retention, retired tables** — `response_items_*` tables left by a previous `ARTIFACT_ENCRYPTION_KEY` are now swept on the same `ARTIFACT_CLEANUP_DAYS` window; before, their rows were kept forever. Each gets its own INFO line. The sweep is skipped while `ARTIFACT_ENCRYPTION_KEY` holds a value the application secret cannot open; the live table is still swept.
- **`SERVICE_ERROR_TEMPLATE`** — a customised template now applies to a picture-only image generation whose reply a proxy, CDN or WAF rewrote, instead of a fixed sentence. The video leg keeps its own card.
- **Video and image catalogs** — a failed catalogue fetch now backs off instead of waiting the whole refresh interval. Retries start at 5 seconds and double (10, 20, 40, 80, 160), capped by `MODEL_CATALOG_REFRESH_SECONDS` when set below 160. Counts are per account and catalog and reset on success; an empty result is not a fault.
- **Update tab** — an apply or restore is now refused when the pipe's source was hand-edited within the same second the tab was drawn; before, the update overwrote the paste and reported success. The revision is now `<updated_at>:<content digest>`, and the refusal is the existing "this view was out of date" message.
- **Provider routing panels** — panels are replaced on the next model-list refresh. An unmappable stored `ORDER`, `ONLY` or `IGNORE` value now warns once at `WARNING`, then at `DEBUG`, instead of three WARNINGs per request. The request is unchanged.
- **inline video and the tool budget** — a turn with an inline video clip on `/responses` no longer shows the "this conversation needs about N tokens" warning or drops a tool result. The budget had priced the clip's base64 about 125x too large. Only inline `data:` clips on `/responses` were affected.
- **Update tab after a refused write** — the Update, Usage and Live tabs now agree on the live generation after a refused write, instead of showing retired sessions or "unavailable".
- **Provider routing** — the per-model endpoint sweep behind the routing dropdowns is now bounded at 45 s in total; with 50 slugs and a slow host it used to hang about 25 minutes and block later schedules. It now logs unfinished models at `WARNING`, and unfinished slugs keep their previous data. `HTTP_TOTAL_TIMEOUT_SECONDS` still limits a single read.
- **provider routing** — the two WARNINGs a generated routing filter raises when healing a stored row no longer include the stored value, only the field and what was kept. Every installed routing filter is rewritten once, silently, on the first model-list refresh; hand edits to a routing row are reverted.
- **Reasoning summary blocks** — on `/chat/completions`, two or more `reasoning.summary` blocks in one round are now separated by one space instead of glued together (`Name the tradeoff.Then weigh it.`).
- **Config tab** — a save the database refuses now raises a durable banner as well as a toast. It names the fault, has no Reload control, keeps staged edits, and clears on the next successful save or configuration load.
- **Auto-update** — the pause line now says why a release was paused: the version it stopped on and the refusal's own sentence. The `(apply manually or restart to re-arm)` hint shows only when it can actually clear the pause.
- **frame reuse** — a frame extracted from a prior video is now bounded to 1920 on its long edge, not width alone. A portrait 4K video now yields 1080x1920 and keeps its continuation frame instead of losing it past `VIDEO_FRAME_IMAGE_MAX_BYTES`. Landscape and small portrait sources are unchanged; 9:16 4K sources lose detail.
- **frame reuse, memory** — the extractor never asks a decoder for a frame over 1920 on either axis, bounding per-frame memory to about 3.7 Mpx and 10.6 MiB. A source whose geometry cannot be measured is now bounded at the decoder too. The ffmpeg pre-child gate, which could never fire at shipped values, is removed.
- **Pipe Dashboard, Config tab** — when two administrators save at once on different workers, one save is now refused with "nothing was saved" instead of being silently lost. The toast names the other save and edits stay staged. Installs without Redis (`WEBSOCKET_MANAGER` unset) behave as before.
- **dashboard** — the System tab's **Readiness** panel now shows memory held by session-log buffers, e.g. `Log buffers (RAM)` reads `2 buf / 40 000 events / 12.4 MB`, and says when a request's records rolled off the record cap.
- **thinking boxes** — a reasoning box that grows mid-answer no longer splits the answer. The stray line break and the duplicate Fusion answer are gone; only a **tool card** still ends a message item. Replay of the next turn no longer carries the break.
- **reasoning summaries** — a provider that fragments one `reasoning.summary` now keeps every fragment; before, all but the last under one `index` were overwritten. Fragments reach the thinking box, closing record and replayed `reasoning_details` once, in order.
- **API callers, streamed** — a 502 on a streamed API call now arrives as a terminal `{"error": {"message": ..., "code": ...}}` frame with the upstream status, not as assistant text in an HTTP 200. Chats, temporary chats, Fusion members and both Anthropic Messages endpoints keep their card.
- **address checking** — `ADDRESS_CHECK_BUDGET_SECONDS` is now spent only by address checks. Slow picture transfers used to eat it, so later video or file links were refused as unfinished checks. Valve help text and docs now say so.
- **pictures** — one request now resolves at most 16 addresses, whatever the picture count; two hundred unfetchable pictures used to cost two hundred lookups. Links past the limit are refused without lookup or download, with the count named.
- **fusion** — a Fusion panel member's tool file is no longer filed against the outer chat. It is still stored and rendered in the panel, but not in the chat's file list.
- **image contracts** — repointing `BASE_URL` now drops the shared published image contracts immediately, not only when a sweep runs. Before, an admin with the four image filter valves off kept the previous gateway's aspect-ratio, resolution and seed limits.
- **provider error row** — for a failure inside an already-started reply, the **Provider error** row now shows the provider's own error type (from `error.metadata.raw.error.type` or `error.type`) instead of an HTTP status or `error`. Custom `{upstream_type}` templates are affected; on a channel chat it is withheld, so a `{{#if}}`-guarded row is left out.
- **API key** — a stored `API_KEY` the key gate refuses now produces the authentication card on the streaming and housekeeping-task legs, instead of a 401 or "Unexpected error in streaming loop". Those legs now use `Pipe._resolve_openrouter_api_key`, so an undecryptable value no longer goes out as an empty `Bearer `.
- **Video turns on the dashboard** — A video turn now books its real tokens and cost on the dashboard instead of zeros, and a failed, clip-less or stalled video counts as Failed rather than Completed. A second request attached to a running video job reports under its own id without that job's usage, so one billed clip is one row's spend.
- **model icons** — Icons are now stored in the orientation they display, so a logo no longer ends up sideways. An icon already stored keeps its pixels until its source URL changes.
- **reasoning budget** — A numeric string for `reasoning.max_tokens` (`"2048"`, `"2048.7"`) is now read as that number on both endpoints and overrides `GEMINI_THINKING_BUDGET` on the Gemini 2.5 leg. A non-numeric value (`"abc"`, `""`, a list, a boolean, `"inf"`, `NaN`) used to fail the turn; it now gives a turn with no thinking budget, silently.
- **responses streaming** — Each SSE frame on `/responses` is now parsed once per turn. A stream whose opening frames a fallback discards no longer keeps their raw bytes in memory.
- **integer request fields** — A non-finite value (`"inf"`, `"nan"`, `"1e400"`, `inf`, `nan`) in `seed`, `max_tokens`, `max_output_tokens`, `max_completion_tokens` or `top_logprobs` no longer kills the turn with an *Unexpected Error* card and a failure-budget strike; the field is sent unset. A bool, list, dict or non-numeric string is still refused.
- **per-model filter installs** — A model's image or video panel failing to install is now warned once per model per kind of failure and repeated at DEBUG, instead of hundreds of identical lines per refresh. `OpenRouter Image filter ensure failed` also warns once per cause and repeats at `DEBUG`.
- **`Files` boxes** — The pipe's own untick of `Files` under `Built-in tools` is now recorded in the model's `openrouter_pipe` metadata as `builtin_tool_defaults`, and applied only on a pass where the pipe unticked `File context` itself. A `Files` box you unticked by hand is no longer changed; rows from earlier releases keep their box.
- **temporary chats in the log** — A temporary chat's browser socket id is no longer logged on the Direct Uploads, dropped-row and artifact-replay paths; those records read `<not retained>`. Saved chat ids are still named in full.
- **`ModelFamily.capabilities`** — Removed; it was an unused accessor kept only for tests. Model capability checkboxes are unchanged, but a third-party plugin calling it would break.
- **Log redaction no longer copies the payload it removes** — Redacting a record with a multi-megabyte picture now costs a few kilobytes instead of a copy. Output is unchanged (base64 runs of 1024+ characters still cut to 64 with the same marker).
- **One user's `Set-Cookie` is no longer replayed onto the next user's request** — Every `aiohttp.ClientSession` now uses `aiohttp.DummyCookieJar()`, so response cookies are discarded. Before, `openrouter.ai`'s Cloudflare `__cf_bm` cookie (not an auth cookie; no credential crossed users) made all users look like one client, and a gateway at `BASE_URL` setting its own session cookie could have leaked it across users (not measured). No valve or timeout changes.
- **Temporary Chat error cards and records** — A temporary chat's socket id, a live handle for `/api/tasks/chat/{chat_id}` and `.../stop`, no longer appears in error cards or related log records. `session_id` is now empty on `temporary:` or `local:` chats; `error_id` and `user_id` remain, and saved and `channel:` chats are unchanged.
- **session log storage** — An archive written under the old path component is now found and merged by the next assembly pass for that turn and republished under the digest name. This happens only when its `meta.json` names that turn's exact `ids`; the old file is left for the retention sweep.
- **session log storage, an over-budget id with no task name** — A caller-supplied message id over 64 characters is now shortened (stem plus digest) on the answer archive too; on PostgreSQL the raw id was refused as `String(64)` and staging failed. Open WebUI's own 36-character ids are unchanged, and an archive under the raw id is merged into the digest-named one.
- **pipe dashboard** — The usage retention window now covers every `dashboard_*` table the pipe published, including ones left by a key rotation, and de-identifies temporary-chat rows. It runs even when `Collect usage records` is off; a table whose fragment another function id also sanitizes to is skipped and logged once, and no table is ever dropped.
- **Pipe Dashboard, action route** — `POST /api/pipe/dashboard/action` now returns `401` when the `WEBUI_AUTH_TRUSTED_EMAIL_HEADER` value names a different person than the token's user, as Open WebUI does; before, such a request could run admin writes (`config_set`, `update_apply`). Nothing changes with the setting off (default) or the header absent or empty. The route also refreshes the caller's "last active" time; both take effect at the next worker restart.
- **Video, prior-video frames** — The prior-video frame is now read as the requesting user, not the storage service account, so a turn with an unresolved user could no longer read anyone's videos. A turn with no signed-in user (e.g. API automation) gets no prior frame and is told "Previous video could not be loaded."; the frame upload is unchanged.
- **Unencodable characters in a provider's reply** — Unencodable characters now reach the card and log record as U+FFFD instead of losing them and the archive.
- **Fusion, Continue of a Fusion answer** — The terminal snapshot no longer replaces the stored answer with only this generation's text on a Continue (a turn with `assistant_message_id`, including `FUSION_BACKEND='openrouter'`), which dropped the half being continued. The `embeds` panel is written either way, and `content` is written only when Open WebUI is not holding it.
- **A refusal that opens a Continue** — A refusal now starts its own block with the separator Open WebUI needs. Before, it could fuse with a stored reply's hidden marker line and lose the continuation's segments. Fresh turns and empty stored replies are unchanged.
- **Unrecognised content block, a link in any letter-case** — Opaque blocks (e.g. `vendor_widget`) are still forwarded, but a block carrying a link is now detected case-insensitively; `HTTPS://169.254.169.254/...`, `FTP://`, `Gopher://` and `//host/x` after a newline used to reach the provider, credentials included. `data:` and `javascript:` URLs stay dropped, and `Api/V1/Files/abc/content` is left alone.
- **A tool's picture that names a host** — An absolute URL in a tool result now goes through the plaintext and address valves (`ENABLE_SSRF_PROTECTION`, `ALLOW_INSECURE_HTTP`); before, one with an `/api/v1/files/` path skipped them and could reach OpenRouter with embedded credentials. Only relative, host-less `/api/v1/files/` references stay exempt; refused pictures are skipped with a status. Cost: an absolute self-link on a private or link-local Open WebUI address is skipped, and dot-segment or query spellings are refused on the tool gate. `/chat/completions` `image_url` file references are now resolved from local storage.
- **Task-model failure notices in shared rooms** — When a task model (titles, tags, follow-ups) fails in a `channel:` or shared saved chat, each member now gets their own one-time notice instead of the first silencing everyone. The related DEBUG lines now name the user id beside the chat id.
- **error templates** — A stored operator template that fences a value on its own lines now renders a code block that closes correctly. Before, a long fence run in the provider body or an indented opener swallowed the closing guidance. Built-in templates are byte-identical.
- **attachments** — A content block whose conversion raises is now dropped and named in the `Files: skipped N (...)` status, instead of being forwarded unconverted. The turn continues with the rest; blocks with no converter still pass through.
- **Video attachments and the file host** — With the opt-ins (off by default): a reference picture over `MEDIA_FILE_HOST_MAX_SIZE_MB` (alone or combined) is left out with a notice naming the cap and the turn proceeds, while a clip or sound file over it still stops the request. The "may have been uploaded" record now covers every attachment on every host with that host's retention, and the second-host failure card says nothing further was uploaded and an earlier attachment is already public.
- **Tool shutdown at `TOOL_SHUTDOWN_TIMEOUT_SECONDS=0`** — The per-request `WARNING` `Tool shutdown exceeded 0.0s; cancelling workers.` no longer appears on this documented quiet setting. Workers are cancelled as before, a genuine timeout still warns once, and a DEBUG line records that the grace period was off.
- **Empty provider-error cards** — When an operator's template renders empty, the stub card now includes `Support email` and `Support link` if set, including on a `channel:` read and in non-streaming `choices[0].message.content`. With neither set (the default) the card is unchanged.
- **Model metadata, a stored grant the access field cannot spell** — On an Open WebUI whose `ModelForm` uses `access_control` instead of `access_grants`, a metadata refresh dropped grants of other principal types (e.g. `anyone`) and a wildcard read dropped the rest of the set. The pipe now refuses the write, keeps the admin's grants, stops refreshing that row's icon and description, and logs one `WARNING` per row. Stock Open WebUI 0.11.4 is unaffected.
- **Video intent, disclosure on long chats** — A chat past the classifier's window (24 rows or 9 prior videos) no longer opens the Intent Disclosure Block on its own, so long chats show fewer blocks. The window note still appears when the block shows for another reason and always under `VIDEO_INTENT_CONFIRM_MODE='always'`; `'never'` still renders nothing.
- **A `data:` header that is not a media type names nothing, on either reader** — Both header readers now accept only a real `type/subtype`, so arbitrary caller text (e.g. a remote `Content-Type: Q4 Payroll - Margit Okonkwo`) is no longer printed. An inline `input_audio` block with a non-media-type header is no longer refused; its `format` decides, defaulting to `mp3`. Media types are lower-cased and log subjects read `data:`.
- **Image generation, the retired size spelling** — An image request using the retired `image_size` no longer fails with a 400 when the model's settings cannot be read; it now goes through the same gate as `size`. `image_size: "banana"` on an unreadable contract is now refused as outside the contract, naming `size`.
- **Open-WebUI-owned tools** — A round only Open WebUI can run (browser-run tool servers, its builtins, or a name withheld under `ask` approval or `function_calling: "legacy"`) is now handed back every turn regardless of `MAX_FUNCTION_CALL_LOOPS`, bounded by `CHAT_RESPONSE_MAX_TOOL_CALL_ITERATIONS`, so such replies run longer and use more of that budget. Skipped-call cards cite a spent budget only when one was really spent.
